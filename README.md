## الجزء 1️⃣ — `site-header.tsx`

### نقاط الضعف السابقة
- 7 أزرار/أيقونات على الموبايل = ازدحام
- تكرار للأيقونات مع bottom-nav (favorites/messages موجودة فيها)
- أيقونة "تقرير المركبة" بحجم زر إضافة الإعلان رغم أهميتها الأقل
- زر "إضافة إعلان" مكرر مع FAB في bottom-nav

### بعد التحسين

**على الموبايل (3 عناصر فقط):**
```
[BC Logo]  ………………  [Profile/Login]
[شريط البحث كامل العرض]
```

**على الديسكتوب (lg+):**
```
[BC + اسم] [Search] [Links] [🔔] [🌗] [+ إعلان جديد] [Profile]
```

### القرارات
- **حذف 4 أيقونات من الهيدر** (المفضلة/الرسائل/تقرير المركبة/زر الإضافة على الموبايل) لأنها موجودة في bottom-nav
- **شريط بحث للموبايل صف منفصل** = يظهر بحجم كامل، أهم إجراء
- **NAV_LINKS مختصرة لـ 3 روابط** فقط على الديسكتوب: الإعلانات / الأقسام / فحص VIN
- **ثيم Toggle و Notifications على sm+ فقط** (الموبايل لديه bottom-nav للإشعارات)

## الجزء 2️⃣ — `app/(public)/listings/page.tsx`

### نقاط الضعف السابقة
- زر "تطبيق" بعد كل تغيير فلتر = خطوة إضافية
- الفلاتر على الجوال = bottom sheet كامل بـ 5 حقول = ثقيل
- حقل بحث داخل الفلاتر مكرر مع البحث في الـ header
- قائمة 1 column على الموبايل = scroll طويل

### بعد التحسين

**1. شريط Chips أعلى الصفحة:**
```
[ ⚙ فلاتر (2) ] [ السيارات ] [ قطع غيار ] [ حافلات ] [ شاحنات ] | [ × طرابلس ] [ × سيارات ]
```
- chips للأقسام السريعة = نقرة واحدة لتصفية بدون فتح أي sheet
- chips للفلاتر النشطة = إزالة بنقرة واحدة (مثل Amazon/AliExpress)

**2. Sort dropdown مدمج** بجانب عنوان الصفحة (بدلاً من نموذج كامل)

**3. Sidebar للديسكتوب فقط** بـ sticky على top-24

**4. Bottom-sheet للجوال** عند فتح "كل الفلاتر":
- Sheet handle بـ rounded ✨
- Footer ثابت بزر "عرض النتائج"
- Close button دائري في الأعلى

**5. الفلاتر تطبَّق فوراً** عند تغيير القسم/المدينة (لا حاجة لزر "تطبيق")
- السعر يطبَّق على blur (لتفادي إعادة الفلترة في كل keystroke)

**6. القائمة 2 columns على الموبايل** بدلاً من 1 column

### Empty state محسَّن
عند عدم وجود نتائج: أيقونة + رسالة + زر "مسح الفلاتر" في كرت متوسط بدل sطر بسيط.

## الجزء 3️⃣ — `app/(public)/add-listing/page.tsx`

### نقاط الضعف السابقة
- 3 خطوات لكن step 2 ضخمة جداً (مواصفات + وصف + موقع + مميزات + عيوب)
- لا scroll للأعلى عند الانتقال بين الخطوات
- الصور في step 3 = المستخدم يكتب كل البيانات قبل أن يفكّر بالصور
- الـ stepper كبير ويأخذ مساحة على الموبايل
- لا preview قبل النشر

### بعد التحسين

**4 خطوات أنظف بدلاً من 3 ثقيلة:**

| الخطوة | المحتوى | لماذا؟ |
|---|---|---|
| **1. الأساسيات** | الصور + العنوان + القسم + السعر | البصر أولاً، ويُجبر المستخدم على رفع صورة قبل المتابعة |
| **2. المواصفات** | ماركة، موديل، سنة، لون، محرك، عداد، وقود، ناقل | كل بيانات السيارة في مكان واحد |
| **3. الوصف والموقع** | وصف، مميزات، عيوب، مدينة، عنوان، خريطة | تركيز على البيع |
| **4. التواصل والنشر** | اسم، هاتف، واتساب + **ملخص الإعلان** + زر النشر | preview + confirm |

### تحسينات تجربة الجوال

1. **Stepper مدمج بشريط تقدم** = `progress = (current - 1) / 3 * 100%`
2. **النقاط قابلة للنقر** للرجوع لخطوات سابقة
3. **scroll-to-top تلقائي** عند تغيير الخطوة
4. **أزرار navigation موحَّدة** بـ ChevronRight/Left الصحيحة في RTL
5. **summary card في الخطوة 4** = preview شامل قبل النشر
6. **Triple auth guard** قبل الرفع (تفادي 403 من Storage)
7. **زر "↑ رئيسية"** على كل صورة لتغيير الصورة الرئيسية بسهولة
8. **"+ مزيد"** كأيقونة في grid الصور = استمرار الإضافة دون فتح ملف جديد

### تحسينات حقول الـ Input
- `inputMode="numeric"` على الأرقام = keyboard رقمي على الموبايل
- `formatPrice()` preview تحت حقل السعر = `65000` يصبح `65,000 د.ل` قبل الإرسال
- counter `0/100` و `0/2000` على الحقول النصية الطويلة
- `Label` component موحَّد مع support لـ `required` + `hint`

### تحسينات الأخطاء
رسائل خطأ محددة لكل حالة من Firebase Storage:
- `storage/unauthorized` → "صلاحية الرفع مرفوضة..."
- `storage/unauthenticated` → "انتهت جلستك..."
- وإلا → الرسالة الأصلية
